Quick start

Open every scene that contains a Unity Terrain. Setup fits a separate deformation volume to each terrain you assign, so you never type a dimension the terrain could work out for you.

  1. Open 57Studios → Deformable Snow Setup. To set up several scenes at once, open them additively in the Hierarchy.

    The preview names each target scene and refuses a slot with no terrain, so a wrong scene cannot be modified silently.

  2. Expand Snow Terrains and add a slot for each terrain. With every slot empty, setup uses the active scene's main terrain.

    Check the preview for each terrain. It lists the scene, volume size, texel size, and capture depth. With Fit to Terrain on, a preferred centre outside a terrain uses that terrain's midpoint.

  3. Press Set Up Rig.

    This builds a volume and test walker for each assigned terrain. Setup replaces the rig in each target scene. Include every terrain you want in those scenes when rebuilding. One Ctrl+Z undoes the setup.

    Save target scenes saves the target scenes that already have files, including their pending edits. Clear Rig in Active Scene removes the rig from the active scene.

  4. Enable the renderer feature.

    Open your active Renderer asset (for example Mobile_Renderer) and tick Deformable Snow Layer in the Renderer Features list. The feature lives in the renderer, not the scene, so setup cannot create it for you.

  5. Press Play.

    Each test walker leaves prints in its volume. Press F1 to inspect the nearest debug heightfield, or use the Validate tab to check the loaded volumes.

The feature ships disabled. If you see no snow at all after setup, this is almost always why — see Troubleshooting.

How it works

Snow deformation is a low-frequency effect. Rather than simulate anything, the addon keeps a small heightfield texture that records where things have pressed, and shades it onto the ground each frame.

Three pieces

  • Each volume is a box over part of a terrain. It owns its heightfield and unloads with that terrain's scene. All visible loaded volumes contribute to the same camera view. A reloaded scene starts with fresh heightfields.
  • Deformers are the objects allowed to press into the snow. A deformer captures its assigned footprint box or the renderers beneath it.
  • The screen-space layer draws the snow. It reads the depth buffer, not a mesh, so it covers the whole terrain without owning any geometry.

Each volume draws its deformers’ footprint boxes and renderer shapes into a thin slab above the ground. Capture rejects geometry above the contact band, blurs the remaining mask, and accumulates it into the heightfield. Refill gradually fades the prints.

// per frame, entirely on the GPU
capture   // deformers -> thin orthographic mask
blur      // separable, softens the print edges
accumulate // height += contact * gain * dt
refill    // height -= refillRate * dt

Nothing is ever read back to the CPU during play. The heightfield stays on the GPU, which keeps the per-frame simulation cheap.

Why there is no snow mesh

An earlier version generated a terrain-conforming mesh to displace. It worked, but it meant keeping a second copy of the ground that had to agree with the terrain exactly — and every bug in that version came from the two drifting apart.

The screen-space layer removes that class of problem entirely. It also means snow follows the camera for free, and lakes and rivers stay visible because transparent water draws after the snow.

Making things leave prints

Deformation is driven by shapes, not physics. Use a footprint box on a bone; use renderers on objects.

Character footsteps

  1. Open 57Studios → Deformable Snow Setup → Characters and click Add Character for each character prefab. For an imported model, assign a prefab variant.
  2. Assign the Character Prefab and use the searchable Foot Bones pickers to select its left and right foot bones. Use Add Foot Bone for extra feet.
  3. Exit Prefab Mode for the target prefab, then click Add Footprints to Prefabs. The tool saves a child with a BoxCollider and DeformableSnowDeformer under each selected bone. In Prefab Mode, adjust the box centre and size to fit the sole. Physics is disabled on the generated box.

Footsteps appear within a snow deformation volume when the box reaches the terrain's contact band. Running setup again adds missing footprints and keeps your existing box settings.

For a player who should leave prints across terrain and roads, enable Add Following Snow Volume before applying the prefab setup. Set Ground Layers on the resulting DeformableSnowFollower to the layers used by the ground and road colliders. The moving volume is 16 m wide and retains prints while they stay within that window.

Other objects

To make an object press into the snow, add a DeformableSnowDeformer component to it or to a parent. Every enabled renderer beneath that object is captured automatically when the deformer has no assigned footprint box.

// anywhere in your gameplay code
var boot = GameObject.Find("Boot L");
boot.AddComponent<DeformableSnowDeformer>();

What actually gates whether an object leaves a print:

RequirementWhy
An assigned footprint box or an enabled RendererEither supplies the shape drawn into the capture mask.
A DeformableSnowDeformerOpts the object in. Nothing is captured by default.
Inside the volume boundsThe volume only captures within its own box.
Within contactBand of the groundKeeps a lifted foot, or a torso, from writing.

To use a box on a custom deformer, assign it in Footprint. The snow capture uses its dimensions even when the collider’s physics is disabled.

A collider alone changes nothing. The capture uses a Renderer or an explicitly assigned footprint box. Physics, collision events, and Rigidbody have no effect. The setup tool strips the primitive colliders from its test rig for exactly that reason.

Put it on the foot, not the character

Captured geometry is flattened into a silhouette. A whole-character deformer records shoulders and head as well as feet when they enter the contact band. Put renderer-based deformers on feet, hooves, props, and dragged objects instead. A footprint box on a bone is the exception: it is a deliberate shape.

Refreshing after changes

The renderer list is built once on enable. If you add, remove, or re-parent children at runtime, call Refresh():

deformer.Refresh();

Turning snow on and off

There are several switches, and they do different things. Use the first one for gameplay.

// stops the snow pass and the prepass it asks for
DeformableSnowLayerFeature.SetLayerEnabled(false);
DeformableSnowLayerFeature.SetLayerEnabled(true);

// read the current state
bool drawing = DeformableSnowLayerFeature.LayerEnabled;

This is static, so gameplay code does not need a reference to the feature. That matters, because the feature is a sub-asset of the renderer asset rather than an object in the scene.

SwitchEffect
SetLayerEnabled(false)Removes the shading pass and the depth-normals prepass it requested. The correct choice for a quality setting.
volume.enabled = falseStops capture and simulation. Snow keeps drawing, it just stops deforming.
_SnowAmount = 0Fades cover to nothing, but the full-screen pass still runs.
feature.SetActive(false)Avoid in gameplay: writes the serialized field, which can persist to disk and mark the renderer asset dirty.

The enabled state is runtime-only and resets to on when scripts reload. If it is driven by a saved graphics setting, apply it on scene load rather than assuming it sticks.

API reference

All types are in the namespace Studios57.DeformableSnow.

DeformableSnowLayerFeature

The renderer feature. Registered in your Renderer asset, not in the scene.

public static void SetLayerEnabled(bool value)

Turns the snow layer on or off everywhere. Callable from any code without a reference to the feature.

Returns nothing. Safe to call every frame.

public static bool LayerEnabled { get; }

Whether the layer is currently drawing. Useful for keeping a settings toggle in sync.

public bool Enabled { get; set; }

The same state, on a single feature instance. Only reachable if you already hold a reference, which the static method avoids needing.

DeformableSnowVolume

Owns the heightfield and the capture pipeline. Setup creates one; you only add your own for a second snow region.

public void Configure(Vector2 size, float surfaceY, float depth, int texels, float depthMetres, float gain, float refill, float contactBandMetres = 0.06f)

Sets every dimension at once. Rebuilds the GPU textures on the next frame if the resolution changed.

ParameterMeaning
sizeWorld XZ footprint of the volume.
surfaceYWorld Y of the deepest point of the snow surface.
depthHeight of the capture slab above surfaceY. Must clear the terrain's height spread.
texelsHeightfield resolution. Rounded to a power of two, clamped to 64–2048.
depthMetresWorld depth represented by a height of 1. The visual snow thickness.
gainHow fast contact accumulates. Higher means prints appear sooner and saturate.
refillHeight recovered per second, so trails fade.
contactBandMetresHow far above the ground an object still counts as touching.

public void SetTerrain(Terrain targetTerrain)

Binds the terrain used to reject lifted geometry. Setup calls this with the terrain you slotted; it only needs calling directly if you build a volume yourself.

public Bounds Bounds { get; }

World-space bounds of the volume, including the capture slab. The shading pass uses this to map world positions into heightfield UVs.

public RenderTexture HeightTexture { get; }

The live compression heightfield. White means fully pressed and black means untouched snow. Read it for gameplay effects, or display it in your own UI.

public void SetDebugMode(int mode)

Shows the heightfield in an on-screen texture. 0 is compression, 1 is the raw capture mask, 2 is the derived normal. Pass -1 to stop. The debug view calls this for you.

public void SetCaptureFlip(bool flipX, bool flipY)

Corrects the capture orientation. Only touch this if prints appear mirrored under your camera setup; the defaults are validated against the standard view matrix.

Read-only properties for diagnostics and tooling: Resolution, WorldSize, HeightTexelSize, SnowDepth, SurfaceHeight, CaptureDepth, ContactBand, CaptureTexture, VisualTexture, DeformerCount, LastCapturedDraws.

DeformableSnowDeformer

A marker component. Add it to anything that should press into snow.

public BoxCollider Footprint { get; } public void SetFootprint(BoxCollider shape)

Reads or sets the box drawn into the capture mask. The capture uses its transform, centre, and size. Pass null to resume capturing renderers.

public void Refresh()

Rebuilds the renderer list. Call after adding, removing or re-parenting children at runtime.

public IReadOnlyList<Renderer> Renderers { get; }

The renderers this deformer contributes when its footprint box is unassigned.

DeformableSnowDebugView

The F1 overlay. Optional outside development.

public void Configure(DeformableSnowVolume targetVolume, bool startVisible, int startMode)

Points the overlay at a volume and sets its initial state. The F1 and F2 keys still work afterwards.

public bool Visible { get; set; } public int Mode { get; set; }

Show or hide the overlay and choose what it displays, from code rather than the keyboard.

Testing utilities

SnowTestWalker, SnowPerfProbe and the Editor assembly exist to validate the feature. They are not runtime API and should not ship in a build.

Tuning

Appearance lives in Materials/PackedSlush.mat and is edited through the Setup window's Appearance tab, so the material asset stays the single source of truth.

Shape of the print

SettingWhat it changes
Contact GainHow quickly a print deepens. Higher saturates sooner, which reads as softer snow.
RefillHow fast trails fade, in height per second. 0.02 clears a trail in about fifty seconds.
Contact BandHow far above the ground still counts as contact. Keep it well under your step lift, or a swinging foot smears into the next print.
Snow DepthHow deep the snow looks. This is the visual amplitude, not the heightfield's storage range.

Where and how much snow

SettingWhat it changes
Snow AmountOverall coverage. Lower values leave ground showing through.
Slope ThresholdMinimum up-facing component that holds snow. Raise it to shed snow from gentle slopes. This is also what keeps grass billboards from being painted flat.
Slope SoftnessSoftens the transition at the slope threshold, so drifts don't end on a hard line.
Detail StrengthGrain and wind ripple, projected in world space.

Texel size is the real constraint

A footprint is only resolvable if it spans several heightfield texels. At the default 8 mm texel the volume covers 8 m and a 14 cm foot spans about eighteen texels. Raise the texel size and the volume grows to match; the print gets coarser in proportion.

If prints look blocky, shrink the volume rather than raising the resolution. More texels over the same area costs memory and buys nothing if the volume is larger than the area you actually walk on.

Debugging

The overlay

Press F1 to show the heightfield, F2 to cycle between the accumulated compression, the raw capture mask, and the derived normal.

If the raw capture shows a foot but the heightfield does not, the problem is in accumulation. If neither shows a foot, the problem is in what is being captured.

The validator

The Setup window's Validate tab correlates the trail against the test rig's patrol line while in Play Mode. It reports whether prints follow the feet and whether individual prints are still separable.

Correlation, not peak height, is the check that matters. A mirrored heightfield still reports a full-height peak, plausible coverage and a correct refill curve — only comparing the trail's direction against the rig catches it.

Measuring cost

// compute chain: capture, blur, accumulate
SnowPerfProbe.StartProbe(volume);

// the screen-space shading pass, measured separately
SnowPerfProbe.StartLayerProbe();

// read the result afterwards
Debug.Log(SnowPerfProbe.LastReport);

Both alternate the feature on and off in short blocks and report paired deltas, because the editor's GPU clock drifts over a long run.

Limitations

These are deliberate trade-offs, not unfinished work. Knowing them will save you time.

  • No silhouette. Snow cannot rise above a rock or drape over a ledge. It shades the ground, it does not add geometry.
  • No snow self-shadowing. Prints shade through the normal, but cast no shadow of their own.
  • Characters need an exclusion layer. Shoulders and heads face upward and would otherwise be painted. Set the feature's Exclusion Layers to your character and prop layers.
  • Alpha-tested geometry is covered. Grass billboards sit in the depth buffer. The slope test rejects cards that face sideways, but how a dense scatter field reads under snow is a visual judgement you should make for your own scene.
  • Water relies on draw order. Lakes and rivers stay visible because transparent water draws after the snow. That is ordering, not a mask.
  • Normals need a prepass. The layer requests a depth-normals prepass so snow shades with the terrain's smooth vertex normals. A custom terrain shader without a DepthNormals pass will fall back to per-triangle shading and look faceted.

Troubleshooting

No snow at all

The renderer feature is inactive. Open the Renderer asset used by the camera and tick Deformable Snow Layer. This is the cause almost every time — the feature ships off, and setup cannot enable it because it lives in the renderer rather than the scene.

Snow looks faceted or low-poly

The layer is falling back to per-triangle normals, which means the depth-normals prepass did not run or your terrain shader has no DepthNormals pass. Stock TerrainLit is fine. If you use a custom terrain shader, add the pass.

Characters are painted white

Set the feature's Exclusion Layers to include your character and prop layers. Anything on those layers is left unpainted.

Prints appear, but not under the feet

For a character prefab, check the selected bones and adjust the box centre under each sole. If the whole trail is mirrored around the volume centre, check SetCaptureFlip and verify with the Validate tab — a mirrored trail still looks like a trail.

Prints merge into one continuous rail

The swinging foot is still inside the contact band, so it writes while it travels. Lower Contact Band, or raise the gait's step lift above it with margin.

Prints never appear

Work down this list: an enabled deformer, an assigned footprint box or an enabled renderer, inside a loaded volume, inside the contact band. If you added children after Play started, call Refresh(). Press F1, then F2 for the raw capture mask — an empty mask means nothing is being captured.

Snow vanishes when you look away

The scene view and game view use separate cameras. The layer draws in both by default; if one is missing snow, check Inject In Scene View on the feature.
